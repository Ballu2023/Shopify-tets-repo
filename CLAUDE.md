# Claude bot: automated Shopify Horizon delivery

This folder is a bot pipeline that turns Figma screenshots + a style guide into a finished Shopify Horizon theme.
The main Claude Code session is the **orchestrator**. It does not write theme code itself; it runs the bots
(subagents in `.claude/agents/`) and keeps the board moving until every section is closed.

Talk to the user (Balwant) in Hinglish (Roman Hindi + English tech terms), short and clear.
Bots write logs on the board in short Hinglish too, so the dashboard reads naturally for the team.

## Folder map

## The flow (enforced by pipeline/board.js)

`backlog → dev (Frontend) → park → uat (UAT) → qa (QA) → fix (Fix) → qa … → closed`
UAT can reject back to `backlog`. After `maxFixRounds` QA→Fix loops a card goes to `blocked` (needs a human).

Bots claim work themselves with `node pipeline/board.js next <bot>`. The CLI makes sure two Frontend/Fix bots
never work on the same page (same template file) at the same time, so parallel bots never overwrite each other.

Data comes first: the Backend bot sets up real collections, products, metafields, metaobjects and images
(`node pipeline/data/setup.js`) before Frontend cards that need that data are built.

## Hard rules for every bot

1. Never publish a theme, never push to the live theme. Push only with `node pipeline/push.js <files>` (unpublished `themeId`).
2. Never edit `pipeline/board.json` by hand. Use the board CLI.
3. Only the Frontend bot and Fix bot edit theme files. UAT and QA only read, test and report. Only the Backend bot changes store data.
4. Do not modify existing Horizon files under `sections/`, `blocks/`, `snippets/` unless the card is explicitly about them.
   New code goes in new files: `sections/custom-<slug>.liquid`, `blocks/_custom-<slug>.liquid` or `blocks/custom-<slug>.liquid`, `snippets/custom-<slug>.liquid`, `assets/custom-<slug>.js|css`.
5. Styling comes from the style guide tokens: wrap custom sections in `class="bot-ui bot-section"`, use `var(--bot-…)` variables and
   `.bot-h1…h6 / .bot-p / .bot-span / .bot-btn-primary / .bot-btn-secondary` classes. No hard-coded hex colours or font sizes.
   Tokens are generated by `node pipeline/tokens.js` into `assets/bot-tokens.css`; rerun it after style-guide.json changes.
   CSS specificity: token rules are emitted as `:where(.bot-ui) .bot-h1` etc., i.e. (0,1,0), so a section's own two-class
   selector (`.custom-<slug> .custom-<slug>__title`) wins normally. Never style a section with a bare single class
   (`.custom-<slug>__title`) — that ties the token rule and loses. Never hand-edit `assets/bot-tokens.css`; it is generated.
   To make a section full-bleed you also need `grid-column: 1 / -1`, because Horizon's `.shopify-section.section` is a grid.
6. All customer-facing text, images, links and repeating items must be editable in the theme editor (schema settings / blocks),
   with the Figma text as defaults. Every custom section has `presets` so it can be added from the editor.
7. Mobile first. Check **375 / 768 / 1024 / 1440** — all four widths are compulsory for UAT and QA, on live computed styles, not just the source. Images via `image_url` + `image_tag` with `widths`, `sizes`, `loading: 'lazy'` (not for the first hero image).
   Never reorder focusable elements with CSS (`order`, `flex-direction: row-reverse`, absolute positioning, or placing a section earlier in the
   DOM than it appears). Tab order follows the DOM, so this silently desyncs keyboard order from visual order — a WCAG 2.4.3 failure. It has
   already caused bugs on the header and the footer. Get the order right in the markup/section order instead, and verify with real Tab presses.
   Anything a touch user can tap must also be reachable by keyboard: check with the drawer/menu/modal open, not just on the closed page.
8. Run `shopify theme check --path "<themeDir>"` on what you touched and fix errors before moving a card.
9. If something is impossible or unclear, log it on the card and release it; do not guess silently.
10. Device-friendly is mandatory: no horizontal scroll at any width, no large empty gaps, tap targets at least 44px.
    Header is one row on desktop and the hamburger layout below 990px.
11. Width rule: ONLY banner sections (hero/slider, full image banners, marquee banner) are full-bleed (100% width).
    Every other section (tiles, grids, carousels, text+image, forms, FAQ, reviews, store locator …) is contained:
    content centred inside `.bot-container` (max-width `var(--bot-space-containerMax)`) with side gutters, even if the Figma frame looks wide.
12. No dummy data. Read `reports/backend/data-map.json` before building: bind tiles/grids/carousels to the real collections and products
    listed there (collection/product pickers with those handles as defaults), FAQ/store lists to the real metaobjects, product details to the
    metafields in `inputs/brief.md`, and images to uploaded files (`shopify://shop_images/<name>`). If the data a section needs is missing from
    the map, log it on the card for the Backend bot instead of hard-coding placeholders.
13. Horizon first. Before writing a custom section, check `sections/` and `blocks/` of the theme: if Horizon already has the section or block,
    configure it through settings/template JSON. Write custom code only for what Horizon cannot do, and say why in the card log.
14. Layout with CSS only. Never use JavaScript to build or rearrange layout (it causes layout jumps and breaks in the theme editor).
    JS is only for behaviour: sliders, tabs, accordions, countdowns, drawers.
15. Shared components: tabs, sliders and similar UI used by several sections live in one shared file (`assets/custom-tabs.css|js`,
    `snippets/custom-…`). Reuse it; do not create a second version. The card that creates it owns it; others only use it.
16. Human feedback wins. A `HUMAN FEEDBACK` entry in a card log (or a message from Balwant) overrides the spec and these defaults.
    Follow it exactly and mention it in the card log when done.

## Page → template map (default)

| Page | Template | Preview path |
|---|---|---|
| Global (header, footer, announcement) | `sections/header-group.json`, `sections/footer-group.json` | `/` |
| Home | `templates/index.json` | `/` |
| About us | `templates/page.about.json` | `/pages/about-us` |
| Contact us | `templates/page.contact.json` | `/pages/contact` |
| PDP | `templates/product.json` | `/products/<any product handle>` |
| PLP | `templates/collection.json` | `/collections/all` |
| Blog | `templates/blog.json` | `/blogs/news` |
| Blog detail | `templates/article.json` | `/blogs/news/<article handle>` |

`inputs/brief.md` can override these. Pages that need a template suffix (about/contact) must exist in Shopify admin with that suffix; the Backend bot handles that.
